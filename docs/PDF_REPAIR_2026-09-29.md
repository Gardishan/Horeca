# Исправление демонстрационных PDF — 29.09.2026

Пользовательская ошибка «Не удалось загрузить PDF-документ» воспроизведена для
всех восьми PDF, доступных Demo Admin в Railway Beta. HTTP возвращал 200,
`application/pdf` и правильную длину, но сам файл не содержал дерева страниц и
xref. Пять fixtures создавал seed/bootstrap, ещё три были историческими
persistence probes. Прежний smoke проверял только `%PDF-` и пропускал дефект.

## Изменение

Общий детерминированный генератор создаёт полноценную одну страницу с отметкой
DEMO ONLY. Его используют seed, bootstrap приватного volume и новые persistence
probes. Независимый pypdf strict parser проверяет читаемость страницы в unit,
локальном HTTP smoke и внешнем smoke; проверяются все пять штатных скачиваний и
скачивание persistence marker. Python нужен только тестам/CI, не приложению.

Bootstrap по-прежнему разрешён только в выключенной demo-only Beta. Явный флаг
`--repair-legacy` заменяет лишь точные известные старые bytes после проверки всех
пяти целей; неизвестное содержимое и symlinks отклоняются. Правильные файлы не
перезаписываются. Seed изменяет только `size` узнаваемых старых demo-документов,
не пересоздавая решения, verification association или review history.

HTTP download endpoints, authorization и продуктовая функциональность не
меняются. PDF-счёт не добавляется: существующее «Сформировать счёт» создаёт запись
счёта и показывает её реквизиты в интерфейсе. Скачиваемое подтверждение оплаты —
отдельный синтетический файл.

## Работающая Beta

Среда: `https://horeca-beta.up.railway.app`, runtime
`00a7b3a03fb6d177aadffb1abf8fa6cbe895bda2`, deployment
`a8ce2c69-21f2-4023-b537-00c86d035620`. 18:17:44–18:17:54 UTC выполнен ограниченный
ремонт данных без нового deployment: восемь точных legacy-файлов заменены после
резервного копирования, затем транзакция согласовала семь размеров документов.
Все остальные поля документов и платёж остались прежними. Права файлов —
UID/GID 1001, mode 0600. Замена атомарна для отдельного файла; общей транзакции
между filesystem и PostgreSQL нет. Оба этапа подтверждены повторным readback.

После ремонта все восемь файлов повторно скачаны через admin API: HTTP200,
PDF MIME, `no-store`, правильные длины, размеры metadata и ожидаемые SHA256.
Каждый PDF разобран pypdf 6.19.0 strict и отрисован PyMuPDF 1.28.2; все восемь
страниц визуально проверены, текст читаем и не обрезан.

подтвердили для каждого файла: без приглашения 401, с приглашением без сессии

документов и одна запись скачивания подтверждения оплаты.

Исторические hashes трёх persistence probes намеренно изменились при этом
ремонте; старые evidence сохраняют исходную дату и не являются проверкой
неизменности файлов после ремонта. Старые локально скачанные копии нужно скачать
снова. Новые probes создаются корректным генератором после доставки этого source.
Не запускать старый bootstrap/seed для восстановления этих файлов.

## Проверка исходников

- `npm run verify` — PASS: 320 tests, TypeScript, lint, coverage и production
  standalone build; независимый review повторил 78 профильных tests.
- Чистые `db:deploy`, `db:seed`, затем `smoke:http` — PASS на изолированном
  локальном PostgreSQL 14.21. Локальный PostgreSQL17 не был доступен; это
  ограничение не скрывается. CI использует PostgreSQL17.
- [Отдельная реальная DB-проверка](audits/2026-09-29/pdf-repair/local-seed-guards.json):
  точный старый размер исправлен, review/все non-size поля сохранены;
  несовпадающие fixture metadata и неизвестный размер не изменены;
  повторный seed идемпотентен.
- Негативные tests отклоняют старые signature-only и обрезанные PDF, неизвестные
  файлы, symlinks и неверные bootstrap conditions. External smoke продолжает
  проверять запрет supplier downloads и приватный cache policy.

Исправление PDF не закрывает остальные найденные блокеры MVP и не доказывает
доставку нового application image. Общая готовность определяется отдельным
MVP registry и внешними проверками точного launch candidate.
