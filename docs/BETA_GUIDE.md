# HoReCa KZ: проверка закрытой MVP Beta

Инструкция для участников закрытой demo-only Beta. Точная версия и результаты запуска фиксируются в `docs/releases/`; текущее состояние среды проверяется отдельно.

Адрес среды: https://horeca-beta.up.railway.app. Используйте только вымышленные компании, контакты и файлы. Реальные документы, персональные данные и платежи запрещены. Demo-кабинеты общие: изменения сохраняются и видны другим тестировщикам. Не запускайте ручную проверку во время rollout.

## Вход и смена роли

1. Откройте `/catalog`. Без приглашения браузер перенаправит на `/beta-access?next=%2Fcatalog`.
2. Введите выданный организатором код в поле **«Код приглашения»**, нажмите **«Открыть контролируемую Beta»**. Код не добавляют в URL, отчёты, скриншоты или переписку об ошибках. Доступ в этом браузере действует до 8 часов.
3. Покупателю отдельная учётная запись не нужна. Для кабинетов откройте `/login` и выберите кнопку:

| Кнопка | Назначение | Стартовая страница |
|---|---|---|
| Active Supplier | Qazaq Coffee & Food Supply, действующий demo-поставщик | `/dashboard/company` |
| Pending Supplier | Fresh Horeca Distribution, demo-компания для ручной проверки | `/dashboard/company` |
| Demo Admin | Модерация компаний, документов, оплат и товаров | `/admin` |

Для смены роли нажмите кнопку **«Выйти»** в шапке, затем снова откройте `/login`. Выход из кабинета сохраняет доступ по приглашению. Для проверки отсутствия приглашения используйте отдельное приватное окно. Самостоятельная регистрация `/register` закрыта; это ожидаемое состояние.

## Покупатель → поставщик

1. Откройте `/catalog/arabica-blend-1kg`, нажмите **«Запросить коммерческое предложение»**.
2. Заполните форму синтетическими данными: например, «Тестовый покупатель», «Demo QA», `+70000000000`, `qa@example.test`. Укажите количество и уникальный комментарий, например «Тест Beta, проверка заявки 26-09-01». Нажмите **«Запросить предложение»**.
3. Ожидайте сообщение **«Запрос отправлен»**. Затем войдите как **Active Supplier** и откройте **«Заявки покупателей»**, `/dashboard/requests`.
4. Найдите тот же товар, количество, комментарий и контакты; новая заявка имеет статус **«Новая»**. В **Pending Supplier** этой заявки быть не должно.

Доставка заявки означает её появление в кабинете. Встроенный ответ, смена статуса заявки и почтовое уведомление в этом сценарии не предусмотрены. Не звоните и не отправляйте письма по demo-контактам.

## Pending Supplier: профиль, тариф, документы

Начните с `/dashboard/company`: проверьте **«Прогресс запуска»** и текущие статусы. Seed уже содержит заполненный профиль, юридические согласия, счёт и подтверждение оплаты на проверке; предыдущие тестировщики могли изменить их состояние.

- `/dashboard/company/profile`: просмотр и редактирование только демонстрационного профиля.
- `/dashboard/company/billing`: **«Выбрать тариф»** → **«Сформировать счёт»**, если нужен новый demo-счёт. Проверьте, что счёт относится к выбранному тарифу. Для загрузки синтетического подтверждения отметьте соответствующее согласие и нажмите **«Загрузить»**. **«Я оплатил»** доступно только с подтверждением демонстрационного характера; это не подтверждает оплату администратором и не активирует компанию.
- `/dashboard/company/verification`: проверьте **«Договор-оферта»** и **«Обработка персональных данных»**; при необходимости нажмите **«Принять»**. Выберите тип документа, загрузите синтетический файл с отметкой demo-согласия. Ожидайте сообщение об успешной загрузке и новую строку в списке. Затем **«Отправить компанию»**: при недостающих условиях должна появиться понятная причина отказа. Повторная отправка уже ожидающей проверки не создаёт дубль.

Для файлов UI допускает PDF, JPG, PNG, DOC или DOCX до 10 МБ. Не маскируйте произвольный файл сменой расширения. Товары неготового поставщика не должны становиться публичными от нажатия «Я оплатил» или «Опубликовать».

## Demo Admin: ручные решения

Откройте `/admin/verifications`, найдите **Fresh Horeca Distribution**. Карточка компании — `/admin/company/company-pending`; список компаний — `/admin/company`.

1. Скачайте синтетический документ и, если доступно, **«Скачать подтверждение оплаты»**. В demo-only Beta допустим статус проверки файла `SKIPPED_MOCK`; он не означает реальное антивирусное сканирование.
2. Для положительного сценария одобрите документы на проверке, нажмите **«Подтвердить оплату»**, затем одобрите верификацию. Операции раздельные.
3. В карточке компании нажмите **«Активировать»**. Успех возможен только при выполнении всех условий; при отказе исправьте указанную причину. Просмотрите **«Журнал действий»**, включая скачивания и решения.
4. У поставщика проверьте обновлённые статусы. Публикация товара выполняется отдельно в `/dashboard/products`; активация компании сама по себе не публикует её черновики.

Для отрицательного сценария используйте **«Отклонить»** / **«Перезагрузить»** / **«Запросить документы»** с обязательным комментарием. Выбирайте один исход для записи: окончательное решение нельзя обратить противоположной кнопкой. После отклонения оплаты нужен новый upload; повторное «Я оплатил» недостаточно. Завершённая verification attempt сохраняется, повторная подача создаёт новую. Не блокируйте основной Active Supplier в рамках обычного прохода: блокировка скрывает его товары у всех тестировщиков.

## Ожидаемые ограничения

| Проверка | Ожидаемый результат |
|---|---|
| Нет приглашения при включённой Beta | Страницы направляют к приглашению; защищённый API — `401 BETA_ACCESS_REQUIRED` |
| Неверный код | Ошибка входа, доступ не выдан |
| Нет входа в кабинет | `/dashboard/*` и `/admin/*` направляют на `/login` |
| Supplier открывает `/admin` | Возврат в кабинет; admin API и приватные admin-download endpoints — `403` |
| Другой поставщик | Чужих заявок и контактов в его inbox нет |
| Upload / сигнал оплаты без demo-согласия | UI не отправляет действие либо API отклоняет его с `422` |
| Не выполнены условия активации или публикации | Отказ без изменения trust/payment status и публичной видимости |
| Оператор выключил Beta | Каталог недоступен с `503 BETA_DISABLED`; readiness — `503 NOT_READY` |

Во время прохода проверьте шапку с предупреждением Beta, читаемые формы и статусы, работу клавиатуры, меню и карточек на узком экране. Пустая страница кабинета, необработанная ошибка или чужие данные — дефект. В отчёт включите время, роль, маршрут, шаги, ожидаемый и фактический результат; приложите correlation ID, если он показан. Не прикладывайте cookie, код приглашения или реальные документы.

Для Android используйте только `horeca-kz-beta-debug.apk` из согласованного **Beta Launch** и сверяйте `APK_SHA256SUMS`. APK из обычного Quality CI настроен на локальный эмулятор. Это debug-артефакт для тестирования, не публикация в магазине.

## Оператор: включение и остановка

Полный контракт, prerequisites и rollback: [docs/DEPLOYMENT.md](https://github.com/Gardishan/Horeca/blob/main/docs/DEPLOYMENT.md#controlled-mvp-beta-profile). Credentials и SSH-ключи остаются в предусмотренном secret store; их значения в этой инструкции не нужны.

**Включение:** после зелёного Quality CI для актуального `main` откройте GitHub Actions → **Beta Launch** → **Run workflow** на `main`. Workflow сначала устанавливает `BETA_ENABLED=false`, затем проверяет runtime, migrations, seed и private files; после preflight устанавливает `BETA_ENABLED=true`, выполняет redeploy, внешний smoke, проверки persistence, APK и rollback/restore. Дождитесь завершения всего run. `VERIFIED_BETA_CANDIDATE` ещё требует release identity и зелёного `npm run mvp:release-check` перед объявлением завершённого запуска.

**Остановка:** в Railway выберите проект `horeca-kz-beta`, среду `beta`, сервис приложения; установите `BETA_ENABLED=false` и примените изменение с redeploy. Дождитесь успешного нового deployment и внешне проверьте `/api/catalog/products` → `503 BETA_DISABLED`, `/api/health/ready` → `503 NOT_READY`. `/api/health/live` должен отвечать `200`: выключение доступа не означает остановку процесса. Одного сохранения переменной без redeploy недостаточно.

После ошибки или отмены run, который уже пытался включить Beta, workflow пытается выключить её и проверить результат. При потере runner или недоступности provider это не гарантировано: оператор должен проверить состояние и при необходимости выполнить остановку вручную.

Новый **Beta Launch** повторяет весь цикл выключения/включения и проверок; он не является простым переключателем и не сбрасывает уже принятые demo-решения. Не запускайте его во время ручного тестирования. Открытый коммерческий запуск, реальные платежи и регистрация новых клиентов этим workflow не разрешаются.
